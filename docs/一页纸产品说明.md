# 明天要用 · 学习教练

**把"这周绕不过去的那件事"，换成三节今天就能用上的课。**
基于三节课企业版开放 API 的即时学习产品 ｜ 可运行 Demo + 本说明

---

## 一、用户需求

企业版给了企业一个大课库，但员工侧的真实状态不是"不想学"，而是**不知道现在该学哪一节**：打开首页几十门课、每门三四个小时，看一眼就关掉。

根因是**颗粒度错配**——

| | 平台提供的最小单位 | 用户真实的需求单位 |
|---|---|---|
| 形态 | 一门课 | 一件事 |
| 体量 | 4 小时 | 20 分钟 |
| 触发 | "我要提升领导力" | "周四要汇报，我怕讲不清" |

学习的触发点从来是一件具体的、有截止日期的工作。而指派制课程把"学"和"用"在时间上拉开了几周，于是员工侧完课率低，HR 侧也拿不出培训有效的证据。

**产品思路：把学习的最小单位从"课"降到"节"，把入口从"课程目录"换成"你这周要做的那件事"。**
四步链路：`说清这件事` → `跨课拆到节` → `排进你的时间` → `直达 + 产出物`

## 二、创新与创意点

**1. 以任务为入口，以"节"为货架单位。** 用 `course/catalog` 把课程拆成 3–14 分钟的最小单元，跨课重组。用户拿到的不是一门课，而是为他这件事临时拼出来的一条路径——同一条路径里可能有汇报课的第 2 节、数据课的第 5 节。

**2. 时间预算是硬约束，不是建议。** 定容装箱，任何一天都不许超时；相关度低于阈值宁可留白也不凑满预算。**签名交互"分钟账条"**：一格一分钟，看得见这 20 分钟花在哪几节上——**它记的是一笔时间账**。

**3. 学习闭环从"学完"移到"用上"。** 每一步都带一个学完立刻做的动作（按内容类型分化：视频→写一句话，模板→当场填一遍，测试→对错题）；整条路径末尾挂一份可交付产出物（汇报提纲 / 反馈话术）。学完的标志不是进度条 100%，是交出了东西。

**4. 零摩擦直达。** 产品挂在企业版首页里，用户已经登录，链接直接指到上课页的那一节，点开就在播。用户从"看到该学什么"到"正在学"是一次点击，中间没有登录、没有找课、没有翻目录。

**5. 双引擎降级设计。** 有大模型走大模型规划，没有 API Key 自动降级为内置规则版规划器，产品完整可用。企业客户的 AI 合规审批周期长，这是能真正落地的工程选择，而不是 Demo 技巧。

## 三、验证、边界与下一步

已跑通四类真实场景（数据复盘汇报 / 跨部门要资源 / 首次负面反馈 / 项目延期止损），每日时长均在预算内，最贴题的节稳定进入路径。

**已知边界**：接口只提供节标题与时长，不提供字幕或正文，语义匹配的精度上限受此限制；时长字段对图文和测试题为 0，需按内容类型估算。

**下一步**：接入事件订阅的"学习进度变更"，把教练从一次性排课变成持续跟进——第 2 天没动就换一条更短的路径，而不是发一条催学通知。

**衡量指标**：建议北极星为 `路径完成率 × 产出物提交率`，而非完课率——后者只能证明视频播完了。
